## 0. 先解决一个悬了很久的问题：奖励曲线为什么全是尖峰

**不是训练不稳定。是策略几乎没在学，而场景方差极大。**

证据：

- 训练日志里 `approx_kl ≈ 1e-4`、`clip_fraction` 恒为 0 —— 策略基本没动
- `environment_reward_total` 逐 update 是 −244 / −293 / −162 / −90 / +1.8 / +266 / −64 / −152 …
  这不是学习曲线，这是**在不同随机场景上采样同一个近似随机策略**的结果
- 闭环评估里 `episode_reward_total` 的标准差 245–287，而均值只有 84–266，**标准差大于均值**

所以你看到的震荡，几乎全部来自"这一批 rollout 抽到了什么场景"，不来自算法。

**这条对论文也有直接影响**：以后所有曲线都必须是"同一冻结 tape、跨 seed 均值 ± 置信带"，
单条原始 reward 曲线在这个方差水平下没有任何可读性，画出来只会被审稿人质疑。
配对比较能把标准误降到 1/2.2 – 1/2.8（已实测）。

## 1. 最重要的一件事：你想做的异构超图，和我发现的架构 bug，是同一个问题

### 1.1 架构 bug 回顾

`clean_offloading_actor.py:151`：任务嵌入在同一决策内对所有候选 UAV **逐行复制**。
所以 HGNN 的输出在选择"哪一架 UAV"这件事上是个**常数**，
它只能调制"该更看重队列还是距离"，**不能直接改变选择**。

而你的 outline §4.1 写的正是"HGNN 每个时隙仅前向一次，得到固定的任务嵌入"——
**这个 bug 会原样带进完整方法。**

**后果非常严重**：等你把 Stage 2 全部搭完、训完，做超边消融的时候，
大概率会发现"去掉超图，指标几乎不变"。那时候已经花掉几个月。

### 1.2 而它的解法，恰好就是你一开始想做的异构超图

把 UAV 也作为节点（只有 5 个，相对几百个 task 节点计算量可忽略），
超边就能表达 **task↔UAV** 关系，于是：

- 超图输出**可以**是逐候选不同的（`z_{ji}` 而不是 `z_j`），能直接影响选择
- 你的代码里本来就存在两类真正的高阶 task-UAV 关系（见 §2）
- **相对 HyperJet 有了实质性区别**（见 §3）

> **你当初的直觉是对的，而且比你现在的方案更好。
> 之前做不出来是工程问题，不是方向问题。**

### 1.3 立刻要做的验证（零训练成本）

**编码器置零消融**：把 encoder 输出整体乘 0，用现有 checkpoint 在冻结 tape 上重评。

- 若 `deterministic_margin20_accuracy` 和闭环指标**几乎不变** → 架构 bug 确认，
  Stage 2 的方案必须先改，**否则整篇论文的主角是废的**
- 若明显下降 → 任务嵌入确实在起作用，问题没那么严重

这个实验只需要一次前向评估，不训练。**它的优先级高于 E1 之后的一切。**

## 2. 你代码里已有、但没被建模的两类真正高阶关系

| 超边 | 代码依据 | 为什么是高阶 |
| --- | --- | --- |
| **共址超边**：同一 DAG 中若分置就会产生 UAV 间传输的任务组 | `assignment.py:354-355`，父子同址时 `continue`，传输为 0 | k 个任务共址省下的传输是 O(k²) 级，**超可加**，成对边表达不了 |
| **资源竞争超边**：同一时隙争抢同一架 UAV 的 ready-task 组 | `TemporaryReservationState` + `remaining_slots > 0`（cap=16） | "这一组的总需求不能超过剩余槽位"是 n 元约束，拆成两两边会丢掉约束本身 |

这两类都是 **task↔UAV** 关系，**必须有 UAV 节点才能表达**。

顺带：无线超图文献（D2D 频谱分配、pilot assignment）用超图的标准论证就是
"多个弱干扰累积成强干扰，成对图说不了 A+B+C 超阈值"。
**你的共址收益和它结构完全同构**，可以直接借用这个已被领域接受的论证形式。

## 3. 相对 HyperJet 的真实差异在哪（这决定论文能不能立住）

HyperJet 的超边类型是 sequence dependency / attribute similarity / attribute correlation。
你 outline §3 的四类（DAG dependency / k-hop / attribute similarity / partition）
**与之高度重合**。如果只有这些，TMC 审稿人会直接问："这和 HyperJet 有什么不同？"

三条候选差异，按强度排序：

### ⭐ 差异一：静态调度 → 在线随机决策（最强，且你已经做到了）

HyperJet 求解的是一个**给定任务集**的联合调度问题。
你的场景是：**UE 随机移动、DAG 随机到达、每时隙重建超图快照、在线序贯决策**。

这不是"同一个问题加个 UAV"，是**从组合优化问题变成了不确定性下的序贯决策问题**。
超图表示必须随 active-task 集合动态更新，这本身就是一个新的技术点。

**建议把 "动态超图快照 (per-slot hypergraph snapshot over active tasks)" 提为一级贡献，
而不是笼统的"用超图"。**

### ⭐ 差异二：异构 task-UAV 超图（需要你去做，但价值最高）

HyperJet 建模的是 task-task 关系。
task↔UAV 的共址与资源竞争高阶关系是**新的**，而且如 §1 所述，
它同时解决了架构 bug。**一举两得。**

### 差异三：顺序预留机制

把 $M^N$ 的联合分配分解为 N 次选择，且保持 EFT 自洽。
这个是扎实的形式化贡献，但**它和超图无关**——
它应该作为第二贡献，不能承担"超图为主角"的论证。

### ⚠️ 不能作为差异的

- "加了 UAV" —— 场景换了，方法没换，审稿人不认
- "用了 RL" —— HyperJet 用什么求解不重要，RL 本身不是贡献
- "E_DAG 超边" —— 二节点，就是普通边，你自己在 §8 已经写清楚了

## 4. 关于"我没有 baseline"——你有，只是没意识到

### 4.1 你已经具备的

`build_clean_task_encoder(encoder_type=...)` 已经支持 **MLP / incidence HGNN /
加权 HGNN / typed-gated HGNN** 切换。这条"无图 → 普通超图 → 区分超边类型"的阶梯
**就是审稿人最想看的消融**，而且基础设施是现成的。

`runs/` 里也已经有 greedy 和 random 的实现。

### 4.2 必须补的（按优先级）

| 优先级 | 基线 | 说明 |
| --- | --- | --- |
| **P0** | **HEFT** | DAG 调度领域的经典基线。这个领域的论文**不带 HEFT 会被直接质疑**。实现成本低，纯启发式 |
| **P0** | **普通 GNN（同参数量）** | 证明超图必要性的唯一方式。必须同参数量，否则不公平 |
| **P1** | **GA-DRL 类 GNN+DRL** | GNN 增强 DRL 做 DAG 调度，是你最直接的竞争者（arXiv 2307.00777） |
| **P1** | **GAT 版本** | 你提到 UAV+图的文章大多是加图注意力。复现一个，直接回答"超图 vs 注意力图" |
| **P2** | **HyperJet 的在线改造版** | 每时隙重解一次。作为强上界，也直接回应"你和对标文章比如何" |
| **P2** | 随机 / greedy-EFT | 已有 |

**"没有 baseline" 不是方向问题，是还没动手。这一项是纯工程量，不是研究风险。**

## 5. 关于 TMC 的现实判断

TMC 是本领域顶刊，审稿严。基于当前状态的坦率评估：

**能立住的前提（缺一不可）：**

1. 超图相对同参数量 GNN 有**统计显著**的提升，且有超边类型级消融
2. 打得过 HEFT 和至少一个 GNN+DRL 基线
3. 超图在架构上**真的能影响决策**（即 §1 的 bug 必须先修）
4. 跨 seed、配对比较、置信区间齐全

**当前距离**：完整方法尚未训练、基线尚未实现、Stage 1 诊断仍在进行。
按这个状态，到可投状态**现实估计 6–12 个月**。这对博士阶段是正常的，但要心里有数。

**你被低估的优势**：冻结 tape、SHA-256 校验、预注册门禁、配对 bootstrap ——
这套可复现性基础设施在期刊审稿中是**加分项**，而且大多数投稿没有。
把它写进实验章节，明确说明配对比较的局限（你 §7 已经写了"只能称匹配初始场景"），
这种诚实在期刊审稿里是有回报的。
