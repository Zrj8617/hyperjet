## 2. 环境的结构性事实

**✅ 当前环境等价于同质并行机的 list scheduling**，这解释了 106–109 的天花板：

| 事实 | 依据 |
| --- | --- |
| 算力同质，`compute_time` 在候选间**完全相同、零判别信息** | `UAV_COMPUTE_RATE_OPS_PER_SEC` 是全局常量（`assignment.py:378`） |
| Stage 1 中 UAV **全程悬停**，传输距离是每 episode 的常数 | `apply_movement({})` → 全体 hover |
| 于是唯一动态的判别维度只剩**队列状态** | EFT = max(now, avail, pred) + transfer + compute + return |

同质并行机上的 list scheduling 有经典近似保证——**greedy 难打不是意外，是结构决定的。**

**✅ 传输比计算贵约 10 倍**：跨机传一次结果 ≈ 4 s，单任务计算 ≈ 0.4 s。
→ **共址（co-location）是理论保证覆盖不到的结构，也是目前最可能的 headroom 来源。**

**✅ 系统工作点**（`long_v1`，稳态）：
完成率 0.80、队列 9.64/16、`k=5` 合法候选占 81.6%、
`min_legal_incremental_delay` p50 = 47 s / p90 = 77 s / p99 = 147 s。
高压但稳定，由 `active_dag_cap=1` 起准入控制作用。

## 3. 已确立的技术结论

| # | 结论 | 证据 |
| --- | --- | --- |
| 1 | **`clip(x/40)` 是真实缺陷** | margin20 上 argmin 保持率仅 **0.1706**；未饱和子集准确率 0.97–0.99 vs 饱和子集 0.57 |
| 2 | **原训练量差 33 倍** | 全程仅 **90** 次参数更新（`ppo_epochs` 决定，chunk 是梯度累积）；`clip_fraction` 恒为 0、`approx_kl≈1e-4` |
| 3 | **补足训练后吞吐翻倍** | 50.41 → 108.48（配对 t = 66.7），零代码改动，只改命令行 |
| 4 | **软归一化消除了排序天花板** | 0.64 → 0.998–0.999；deterministic EFT regret 23–26 s → 0.13–0.16 s |
| 5 | **但闭环同时下降 15%** | 108.48 → 92.16（配对 t = −14.4），20 场景中 16 降 |
| 6 | **`-EFT regret` 不能作为最终目标** | 模仿类目标上限即被模仿对象；greedy 自己就是 108.65 |
| 7 | **任务顺序没有 leverage** | 两种机制**相反**的排序（`rank_u` 降序 / `dag_remaining_asc`）效应均被限制在 ±10，CI 跨 0 |
| 8 | **纯负载均衡没有价值** | `shortest_queue` 55.50，仅比 random 好 7.4 |
| 9 | **`dag_completion_rate` 是被混淆的指标** | 分母 `generated_dag_count` 依赖策略，实测污染 8.5%–47% |
| 10 | **奖励 clip 不生效** | 触发阈值 = 60 × 10 = **600 s**；实测 delay p99 = 147 s、max ≈ 417 s |
| 11 | **回报方差是均值的三倍** | 冻结策略下 `episode_reward_total` 标准差 245 vs 均值 84 → **不要画单条训练回报曲线** |

## 4. 已确立的架构问题

**✅ 超图在当前架构下影响不了卸载决策**（纯代码事实）：

- 任务嵌入在同一决策内**逐行复制**到每个候选（`clean_offloading_actor.py:151` `np.repeat`）
  → 编码器输出对"选哪架 UAV"是常数
- 决策顺序被 `_ready_sort_key` 冻结 → 也影响不了排序
- 旁证：Stage 1 强制 `encoder="mlp"`（完全不用图），未饱和区照样 96–98%

**⚠️ 尚缺实证**：A2 打乱消融从头到尾没有跑过。

**✅ 超边构成**：`E_DAG` 是二节点（等价普通边）；`E_khop` 多节点但 k 层 GNN 可覆盖；
**`E_attr` 是四类里唯一既多节点、又不能被普通 GNN 平凡复现的**；`E_part` 冗余度高。

**✅ 相对 HyperJet(INFOCOM'25) 的新颖性风险**：其超边类型（序列依赖 / 属性相似 / 属性关联）
与现有四类高度重合。可辩护的差异是**动态超图快照**（在线随 active-task 集合逐时隙重建）
与 **task↔UAV 异构超图**（HyperJet 只建模 task-task）。

## 9. 决策树

```
共址测试（免费）
├─ 有显著 headroom → 超图机制成立，进 Phase B（异构 task-UAV 超图）
└─ 无 headroom
      ↓
   A2 打乱消融（免费）
   ├─ 嵌入路径无效 → 架构必须改，且共址无 headroom = 天花板可能是真的
   └─ 打开移动（代码现成，仅被冻结）
         ├─ 出现 headroom → 移动是主要杠杆，movement actor 必须保留
         └─ 仍无 headroom → 启用异构算力（config 里已有，主线未接）
```

**优先级**：共址 > A2 > 打开移动 > 单点验证（#3）> 修 critic 测试 > 异构算力

前两项一分钱不花，且能在几天内判定天花板是否为真。

## 10. 论文相关

### 可直接使用

- 基线表（§1）
- 「EFT 是主信号」：106–109 vs 48–56
- 「排序准确率不预测吞吐」：0.64 → 108.48，1.00 → 108.65
- 可复现性方法学：冻结 tape、配对 bootstrap、预注册门禁

### ⚠️ 诚实性红线

**B1 之前那个 108.48 是特征截断缺陷的副产物，不是设计产物。**
论文中**不得**表述为「我们的方法比 greedy 好」。
必须用**有意设计的**基线证明 EFT-greedy 次优，本方法再超过它。

### 定位建议

- 一级贡献候选：**动态超图快照**（在线逐时隙重建）+ **task↔UAV 异构超图**
- 二级贡献：**顺序临时预留机制**（$M^N$ → N 次选择且 EFT 自洽）——**需补消融**
- 必补基线：HEFT（已有）、同参数量 GNN、GAT、GA-DRL 类
- 目标：TMC
