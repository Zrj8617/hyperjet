### 还有第二处同源的 clip（在奖励里）

`config.py:122-123`：

```python

CLEAN_REWARD_TIME_CLIP: float = 10.0   # 时延惩罚被截断
```

注释写着"避免长队列产生的极端时延压过 DAG 完成奖励"。

> **奖励无法区分"迟到"和"灾难性迟到"。**

**这才是"不收敛"的完整机制**：观测端和奖励端在同一个工作点上一起饱和，

不是"RL 调参没调好"。

## 1. 场景够不够创新，细节设置对不对

### 1.1 创新性：坦率说，场景本身不构成创新

"UAV 辅助 MEC + DAG 任务卸载 + 多智能体 RL" 是一个非常拥挤的方向。
5 架 UAV、60 个 UE、hotspot 移动模型、队列上限、Gauss-Markov 游走——
这些设置在这个领域是标准配置，审稿人不会因此给分。

**但你的代码里有一个真正的形式化贡献，而且比超图更硬：**

> `TemporaryReservationState` + 时隙内顺序决策
> （`environment/assignment.py:47-109`、`clean_offloading_actor.py:113-196`）

把"一个时隙内把 N 个 ready task 分配给 M 架 UAV"这个组合动作，
分解成 N 次顺序选择，并用临时预留状态保证每一步的 EFT 估计
**对前面已做出的决策是自洽的**。这解决了一个真问题：
朴素做法要么动作空间是 M^N，要么各任务独立决策导致 EFT 估计互相矛盾（都去抢同一架最空的 UAV）。

这个设计值得在论文里单独成节，配一个"独立决策 vs 顺序预留"的消融。
**它比超图更容易被审稿人接受，因为它解决的问题是可见的。**

### 1.2 细节设置：三个我认为需要改的

**(a) ρ > 1 —— 最该改的一个**

后果不只是"系统很堵"，而是：

- 完成率被容量而非策略决定，seed 间标准差高达 **0.099**——
  审稿人一定会问"为什么你的完成率在 0.68 到 0.93 之间跳"；
- 想证明 RL 优于 greedy，在 σ=0.099 下需要约 20 个百分点的提升才显著。
  这个门槛几乎不可能达到；
- `offloading_skipped_total` 在 greedy 下是 **286 ± 423**——
  有些 seed 跳过上千个任务（队列满，无合法候选）。
  这时策略根本没有决策空间，样本被浪费。

**建议目标：ρ ∈ [0.7, 0.95]。** 在这个区间里策略差异才是完成率差异的主因，
方差会显著下降，而且系统仍有拥塞（否则随便分配都能全完成，也没得学）。
调 `DAG_BASE_ARRIVAL_PROB` 或 `UAV_COMPUTE_RATE_OPS_PER_SEC` 都可以，
前者更好解释（"负载水平"是论文里可以扫的自变量）。

**(b) UAV 算力完全同质**

`assignment.py:378`：`compute_time = task.num_operation / config.UAV_COMPUTE_RATE_OPS_PER_SEC`
——一个**全局常量**。所以 `compute_time` 在同一决策的所有候选间**完全相同，零判别信息**。

`config.py:382` 里其实有 `UAV_COMPUTING_CAPACITY`（每架 UAV 5–20 GHz 随机），
但只被旧路径（`environment/uavs.py`、几个老脚本）使用，clean 主线没接。

异质算力会带来：更贴近现实、候选间多一个真实判别维、
以及一个 greedy-EFT 不那么容易做对的决策（要在"近但慢"和"远但快"之间权衡）。
**这是给 RL 制造学习空间的最低成本改动。**

**(c) 奖励里的能耗项可能撑不起论文声明**

`REWARD_ENERGY_WEIGHT=0.1`、`REWARD_MOVEMENT_ENERGY_WEIGHT=0.05`，
相对 `REWARD_COMPLETED_DAG_WEIGHT`（Stage 1 实际用 16.0）几乎可以忽略。
如果论文要声称"联合优化时延与能耗"，需要真的做能耗-时延 Pareto 前沿，
否则建议在论文里**弱化能耗声明**，只做时延/完成率。少声明不丢分，声明了做不出来才丢分。

## 2. 超图 + 无人机 + 强化学习到底能不能做

**能做，能发。但"三者结合"本身不是贡献**——这类论文已经很多。
贡献必须落在"为什么这个问题需要超图，而普通 GNN 不够"。

### 2.1 当前超图设计的问题（这是最大的发表风险）

我读了 `environment/graph_builder.py:306-320`：

```python
def _build_dag_hyperedges(...):
    for task in active_tasks:
        for child_id in sorted(task.successors, ...):
            hyperedges.append(sorted([parent_idx, task_id_to_idx[child_id]]))
```

**E_DAG 生成的是 2 节点超边，也就是普通的边。** 这不是高阶结构。
审稿人只要看一眼超边基数分布，就会问"你的超图为什么大部分超边只有 2 个节点"。

按之前的评估，四类超边里：
- **E_DAG**：2 节点 = 普通边，图可平凡替代；
- **E_khop**：k 跳邻域，普通 GNN 叠 k 层即可等价，图可平凡替代；
- **E_part**：KaHyPar 划分，与 GNN 深度冗余，且引入了很重的外部依赖；
- **E_attr**：目前唯一有高阶语义的。

也就是说：**当前这个"超图"在很大程度上是加了包装的图。**
我知道这句话不好听，但审稿人会先想到这一点，你现在知道比投稿后知道好。

### 2.2 这个问题里真正的高阶关系是什么

好消息是，你的问题域里**确实存在**天然的高阶关系，只是现在没被建模：

| 候选超边 | 语义 | 为什么普通图做不了 |
| --- | --- | --- |
| **资源竞争超边**：本时隙所有 ready task 中竞争同一架 UAV 的那一组 | n 元竞争，且随分配动态变化 | 竞争是"这一组一起争一个资源"，拆成两两边会丢失"总量超限"这个约束本身 |
| **共址超边**：同一 DAG 中若分开放置就会产生 UAV 间传输的任务组 | n 元协同放置 | 收益是超可加的——3 个任务放一起省的传输 > 三条两两边之和 |
| **干扰/带宽共享超边**：同一 hotspot 内共享上行带宽的 UE 组 | n 元资源共享 | 带宽是被整组瓜分的，不是两两分的 |

前两个和你的调度目标直接相关，而且**恰好是 greedy-EFT 做不好的地方**（见 §3）。
如果超图要在这篇论文里立得住，应该往这个方向重做，而不是修补现有四类边。

### 2.3 消融是必须的，不是可选的

无论怎么改，论文必须有：`超图 vs 同参数量的普通 GNN vs 无图 MLP`。
好消息是**你已经有了这个基础设施**——`build_clean_task_encoder(encoder_type=...)`
支持 `mlp`，Stage 1 用的就是 `mlp`。也就是说你的 Stage 1 结果本身就是"无图 MLP"这一档。
这是个意外的便利，别浪费。

## 3. 当前的修改方向真的对吗

### 3.1 一个必须纠正的认知：Stage 1 没有"不收敛"

D0 已经给出证据：**在特征未饱和的样本上，actor 的 margin≥20 准确率是 96–98%。**
30 个 update、约 10⁴ 个决策就达到了。这不是不收敛，这是**收敛得很好**。

失败只发生在特征被 clip 成常数的样本上——那里没有信息可学，任何算法都学不会。
所以"我的实验不能收敛"这个描述，至少对 Stage 1 是不成立的。
你遇到的是一个**特征工程 bug + 工作点标定问题**，不是 RL 训练问题。

这个区分很重要，因为它决定你该找谁帮忙：不需要 RL 调参专家，需要把数据流理清楚。

### 3.2 但有一个更根本的问题：Stage 1 的目标就是 greedy 本身

`marl_models/mappo/clean_decision_ppo_bandit.py:170-175`：

```python
legal_best = float(eft[mask].min())
raw_regrets[mask] = np.maximum(eft[mask] - legal_best, 0.0)
rewards = -raw_regrets / scale
```

Stage 1 的 reward **精确等于负 EFT regret**，也就是说：

> **Stage 1 训练的目标，就是让策略变成 greedy-EFT。**
> 它的性能上界就是 greedy，永远不可能超过 greedy。

这没错——作为热启动它是合理的。但要清楚：
**Stage 1 做到 100% 也产不出任何论文结果。**
论文的全部价值在 Stage 2——RL 能否**超过** greedy。

而实测 greedy 已经很强：completion 0.785 vs random 0.526。
所以真正的问题不是"RL 能不能收敛"，而是：

> **RL 到底靠什么超过 greedy？**

这个问题现在没有答案，而它比 clip 重要一个数量级。

### 3.3 我的答案：靠 greedy 结构上做不到的两件事

greedy-EFT 是**逐任务、无前瞻、无 DAG 意识**的。它必然做不好：

1. **DAG 级优先级**：一个还差 1 个任务就完成的 DAG，和一个刚到达的 DAG，
   greedy 一视同仁。但完成前者立刻拿到完成奖励，后者要等很久。
   这是典型的长视野信用分配问题，正是 RL 该赢的地方。
2. **依赖任务共址**：把父子任务放同一架 UAV 可以省掉 UAV 间传输。
   greedy 只看当前任务的 EFT，会为了眼前几百毫秒把子任务推到别的 UAV，
   反而在下一步付出更大传输代价。

**这两条同时也正是 §2.2 里两类高阶超边的语义。**
如果这条线走通，超图的必要性和 RL 的必要性会由同一个机制同时得到支撑——
那才是一篇有骨架的论文。

### 3.4 所以修改方向的排序应该是

| 优先级 | 动作 | 理由 |
| --- | --- | --- |
| **P0** | 在当前 Stage 1 配置下实测 ρ 和队列演化 | 决定后面所有事。零成本 |
| **P0** | 把 ρ 调到 [0.7, 0.95] | 不做这个，后面所有对比都淹没在方差里 |
| **P1** | 复测 clip 饱和率 | ρ 修好后饱和率可能自己降下去，clip 也许根本不用改 |
| **P1** | 用现有 baseline 量化 greedy 的 headroom（见 §5 第 3 步） | 决定这篇论文有没有可做的空间 |
| **P2** | clip 修复（若 P1 后仍饱和） | 真 bug，但不产出论文结果 |
| **P2** | UAV 算力异质化 | 低成本增加决策难度 |
| **P3** | 超边重做（资源竞争 + 共址） | 论文核心贡献，但要等 P0/P1 确认框架成立 |

**注意 P0 的两条都在"改环境/容量"里，是你上一轮明确排除的范围。**
但 D0 的证据把这个约束推翻了：不改工作点，clip 修好也只是把一个饱和问题
换成另一个饱和问题。这需要你重新授权。

## 4. 是否收敛到底怎么看

先分清两件常被混为一谈的事：

- **(A) 优化收敛了吗** —— 训练过程本身稳定、损失/回报不再变化
- **(B) 策略好不好** —— 相对基线有没有优势

**(A) 成立但 (B) 不成立，是这个领域最常见的自欺。** 你现在的 Stage 1 就是典型：
优化收敛得很漂亮（未饱和区 96–98%），但策略上界只是 greedy。

### 4.1 判断 (A)：训练稳定性

Stage 1（bandit，字段都在 `logs/decision_ppo_bandit/*/updates.jsonl` 里，已经记了）：

| 指标 | 收敛的样子 | 出问题的样子 |
| --- | --- | --- |
| `behavior.raw_eft_regret_mean` | 下降后走平 | 一直降 = 还没训够；上升 = 发散 |
| `update.epochs[].approx_kl` | 稳定在 0.005–0.02 | > 0.05 = 步子太大；≈ 0 = 没在学 |
| `clip_fraction` | 0.05–0.3 平稳 | 持续上升 = 策略漂移过快 |
| `ratio_std` | 平稳 | 变大 = 新旧策略脱节 |
| 3 个 seed 的曲线 | 互相重叠 | 分叉 = 结果不可复现 |

Stage 2（完整 PPO，会多出 critic 和 GAE）额外必须看：

| 指标 | 为什么关键 |
| --- | --- |
| **critic explained variance** | **最重要、也最常被忽略的一个**。< 0 表示 critic 还不如直接用均值预测，此时 GAE 算出的 advantage 基本是噪声，policy 学到的东西没有意义。必须 > 0 并稳定上升 |
| value loss | 下降后走平 |
| policy entropy | 缓慢下降。**早期就掉到接近 0 = 过早收敛**，几乎必然是次优解 |
| grad norm | 平稳，无尖峰 |
| episode return | 均值 ± 跨 seed 标准差，≥ 5 个 seed |

### 4.2 判断 (B)：相对基线 —— 而且要用配对比较

**"收敛"离开基线是没有意义的。** 判据应该是：

```
RL 均值 − greedy 均值  >  2 × 合并后的 seed 标准差
```

按当前 σ ≈ 0.099，这要求约 20 个百分点的提升。**做不到。**

**但你有一个现成的办法把这个门槛降一个数量级——你自己已经建好了：**

`environment/stage1_temperature_tape.py` 的冻结 tape 给出**逐 bit 相同的场景材料**
（DAG 模板、UE 初始位置、移动增量、到达 uniform 全部固定）。
在同一条 tape 上跑 greedy / random / RL，得到的是**配对样本**，
可以做 paired bootstrap——你甚至已经实现了
（`stage1_temperature_analysis.py:140` `paired_scenario_bootstrap`）。

配对比较消掉了场景难度带来的方差（那正是 σ=0.099 的主要来源），
统计功效会大幅提升。**这套基础设施是你目前最被低估的资产，
它现在只用在温度对比上，应该扩展成所有策略对比的标准评估通道。**

### 4.3 一句话判据

> 在冻结 tape 上、跨 ≥5 个 seed、做配对比较，
> RL 的 DAG 完成率（或平均 flowtime）相对 greedy-EFT 的改进，
> 其 95% bootstrap 置信区间下界 > 0。
>
> **这个条件成立之前，"收敛了"没有任何意义；成立之后，才有论文。**
