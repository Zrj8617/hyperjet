# HyperUAV 下一步方案（2026-08-07）

目标：TMC，超图为主角。
原则：**每个阶段都以"能否证伪"为闸门，不通过就不往下走。**

---

## 一个先要说清楚的判断：Stage 1 的定位变了

Stage 1 原本的定位是"预训练一个可以继承的 checkpoint"。
但现在已经明确：**最终架构需要逐候选的任务嵌入（`z_ji` 而非 `z_j`），
actor 输入会发生结构性变化，当前 Stage 1 的 checkpoint 无法迁移。**

所以：

> **Stage 1 从"预训练产物"降级为"诊断工具"。**
> 只需要从它身上取走两个答案（clip 是不是瓶颈、表示路径通不通），
> **不要再为了把它的指标做好看而投入额外的训练轮次。**

这个重新定位能省掉不少无谓的循环。

---

## Phase A —— 诊断收尾（三个实验，互相独立，本周内做完）

三个结果**必须一起看**才能定架构。任何一个单独出来都不足以决策。

### A1. 长训练（E1，进行中）

**回答**：64–67% 的选对率是训练不足，还是特征截断的天花板？

判据已预注册：`deterministic_margin20_accuracy` < 0.75 → clip 是瓶颈；
≥ 0.90 → clip 假设推翻；中间 → 停下来讨论。

### A2. 编码器消融（等 A1 跑完，用**旧 checkpoint** 即可）

**回答**：任务嵌入这条路，现在到底有没有在起作用？
这决定超图将来能不能起作用，因为超图正是从这条路进来的。

两个变体，**以打乱版为准**：

| 变体 | 做法 | 说明 |
| --- | --- | --- |
| **打乱（主）** | 任务 i 的嵌入换成随机另一个任务的嵌入 | 数值分布不变，只破坏"嵌入↔任务"的对应关系。干净 |
| 置零（参考） | 64 维全部置 0 | 简单，但超出训练分布，结果偏悲观 |

在冻结 tape 上重评，比 `deterministic_margin20_accuracy`、
`completed_dag_count`、`average_dag_flowtime`。

**判读**：
- 打乱后指标几乎不变（差异 < 2%）→ **表示路径无效，架构必须改**
- 明显下降 → 嵌入在起作用，架构问题没那么严重

### A3. Headroom 测试（无模型，零训练）

**回答**：这个环境里，到底存不存在 greedy-EFT 拿不到的收益？
**这是整个项目最关键、也最可能带来坏消息的一个实验。**

在冻结 tape 上跑几个纯启发式，配对比较 `completed_dag_count`：

**第一组：固定任务顺序（当前动作空间内）**

1. greedy-EFT（基准）
2. 共址优先：优先选持有该任务最多前驱的 UAV，EFT 做次级排序
3. 前瞻容量：优先选"还留得下该任务后继"的 UAV
4. 最短队列

**第二组：改变任务处理顺序（超出当前动作空间）**

5. greedy-EFT + 按"DAG 剩余任务数升序"处理任务
6. greedy-EFT + 按"DAG 已等待时间降序"处理任务

第二组很重要，因为当前 `_ready_sort_key` 把任务顺序**写死**了
（按 DAG 到达时间、dag_id、拓扑序）。如果收益主要来自第二组，
说明**决策顺序本身应该交给策略学**，这会是一个独立的贡献点，
也会改变 Stage 2 的动作空间设计。

**判读**：
- 有启发式显著超过 greedy-EFT → RL 有可赢空间，方案成立
- 第一组赢不了、第二组能赢 → leverage 在顺序上，动作空间要改
- 全都赢不了 → **最坏情况**，环境里没有值得学的结构，
  必须先改场景（异构算力、更紧的耦合、截止期约束等）再谈方法

## Phase A 三个结果的决策表

| A1 | A2 | A3 | 结论与动作 |
| --- | --- | --- | --- |
| clip 是瓶颈 | 路径无效 | 有 headroom | **最可能的情况**：Phase B 两件事都做，顺序执行 |
| clip 是瓶颈 | 路径有效 | 有 headroom | 只修归一化，架构改动可以小一些（但 UAV 节点仍建议加，因为那是相对 HyperJet 的差异） |
| 训练不足为主 | 路径无效 | 有 headroom | 不动归一化，直接做架构 |
| 任意 | 任意 | **无 headroom** | **停止方法开发**，先改场景。这是唯一需要推翻计划的分支 |

## Phase B —— 架构定型（Phase A 通过后，1–2 周）

**分两步做，不要合并**，否则出问题无法归因。

### B1. 归一化修复（先做，便宜且可单独验证）

- 把 `incremental_delay` 与 `queue_waiting_time` 的 `clip(x/40, 0, 1)`
  换成不截断的保序变换（建议 `x/(x+ref)`，`ref` 取实测中位数附近，约 70–100 s）
- 同时检查 dynamic 特征第 5 维 `available_delta`（**共用同一个 40 s 参考值**，很可能一起饱和）
- 重训 Stage 1，在**同一条冻结 tape** 上验证

**闸门**：`deterministic_margin20_accuracy` ≥ 0.90；
全候选饱和率 ≤ 5%；**未饱和子集的准确率不低于当前的 0.96**（防退化）。

### B2. 异构 task-UAV 超图（核心贡献）

- 图中加入 UAV 节点（仅 5 个，计算量可忽略）
- 新增两类真正的高阶超边：
  - **共址超边**：同一 DAG 中分置会产生 UAV 间传输的任务组
  - **资源竞争超边**：同时隙争抢同一架 UAV 的 ready-task 组
- 让编码器输出**逐候选**的嵌入 `z_ji`，接到 scorer 的候选行上

**闸门**：重跑 A2 的打乱消融，这次必须出现**明显下降**——
否则说明新架构仍然没把表示接进决策。

## Phase D —— 完整方法与消融矩阵

只有 A、B、C 全部通过才启动。届时的消融矩阵：

- 表示：无图 MLP / 普通 GNN / GAT / 基础 HGNN / typed-gated HGNN（**基础设施已有**）

- 机制：去掉临时预留 / 固定 UAV 移动 / 固定任务顺序
- 负载：扫 `DAG_BASE_ARRIVAL_PROB`，作为敏感性分析

## 实验呈现方式（从现在起统一）

1. **不画训练回报曲线。** 方差是均值的三倍，画出来会被质疑。
2. 画**冻结 tape 上的评估曲线**，跨 ≥5 seed 的均值 ± 95% 置信带。
3. 主指标 **`completed_dag_count`**，不用 `dag_completion_rate`
   （分母 `generated_dag_count` 依赖策略，实测污染 8.5%）。
4. 所有方法对比走**配对 bootstrap**（已实测功效提升 2.2–2.8×）。
5. 诚实声明配对的局限："匹配初始场景，非逐决策严格反事实"——
   outline §7 已有，保留。
