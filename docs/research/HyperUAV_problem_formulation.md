# HyperUAV 优化问题形式化（草稿 v0.1 · 待与师兄敲定系数）

> 目的：先写 **(P1) 目标 + 约束**，再由 `r_k = −Δ_k J` 推导奖励。
> 当前代码**没有**显式目标函数，奖励权重是手调的（`调优v8`），这份文档就是补这个缺口。

## 1. 系统与决策变量

- UAV 集合 `U`（|U|=5）、UE 集合 `I`（|I|=60）、时隙 `n=1..N`（N=500，每隙 δ=5s）
- DAG 作业随机到达：每 UE 每隙以 `p_a` 到达（基础 0.0145，热点内 ×2），**每 UE 至多 1 个在途 DAG**
- 每个 DAG `g` 含任务集 `V_g`（5–8 个）与依赖边 `E_g`
- **策略 φ 输出两类决策：**
  - 移动：`a_u[n] ∈ {hover, +x, −x, +y, −y}`
  - 卸载：`x_{τ,u}[n] ∈ {0,1}`，任务 τ 分配给 UAV u

## 2. (P1) 优化问题

```
(P1)  min_φ  J(φ) = lim_{N→∞} E[ ( Σ_{g∈G(N)} [ F_g + P·(1−c_g) ]
                                   + λ_E · Σ_{n=1}^{N} Σ_{u∈U} E_u[n] ) / |G(N)| ]
```

其中：
- `G(N)`：N 个时隙内到达的 DAG 集合
- `c_g ∈ {0,1}`：DAG g 是否完成（所有子任务算完 **且** 结果回传到 UE）
- `F_g = T_g^finish − T_g^arrive`：DAG 流时间（flowtime）
- `P`：**未完成 DAG 的惩罚**（不可省，否则策略可只挑易做的 DAG 来压低平均 flowtime）
- `E_u[n] = E_u^comp[n] + E_u^comm[n] + E_u^move[n]`：UAV u 在该隙的计算+通信+移动能耗
- `λ_E`：能耗与时延的权衡系数

**s.t.**

| 约束 | 含义 | 代码现状 |
|---|---|---|
| (C1) `Σ_u x_{τ,u}[n] = 1` | 每个被调度的就绪任务恰分配给一架 UAV | ✅ 已强制 |
| (C2) `s_τ ≥ max_{τ'∈pred(τ)} ( f_{τ'} + t^{tr}_{τ'→τ} )` | DAG 依赖 + 跨 UAV 输出传输 | ✅ 已强制 |
| (C3) `\|Q_u[n]\| ≤ Q_max = 16` | UAV 队列容量 | ✅ 已强制 |
| (C4) `t^{comp}_τ = c_τ / f`，UAV 串行处理 | 算力约束（f = 1e6 ops/s，**当前所有 UAV 同构**） | ✅ 已强制 |
| (C5) `t^{tx} = D·8 / (B·η(d))`，`η(d)=1/(1+(d/100)²)` | 通信速率与距离衰减 | ✅ 已强制 |
| (C6) `p_u[n+1] = p_u[n] + δ·v·a_u[n] ∈ [0,W]×[0,H]` | 移动与边界（v=15 m/s） | ✅ 已强制 |
| (C7) `‖p_u[n] − p_{u'}[n]‖ ≥ d_min` | UAV 最小安全间隔（config 写 200m） | ❌ **声明了但未强制** |
| (C8) `‖p_u[n] − p_τ‖ ≤ d_max` | 任务—UAV 可达距离（config 写 220m） | ❌ **声明了但未强制** |

⚠️ **(C7)(C8) 必须二选一处理**：要么在代码里真正强制，要么从论文的问题描述里删掉。现在写进论文而代码不执行，是审稿人一查代码就会发现的硬伤。

## 3. 由 J 推导逐决策奖励

第 k 个调度决策对 J 的边际贡献取负：

```
r_k = −Δ_k J = − [ ( T̂_g^{(k)} − T̂_g^{(k−1)} )  +  λ_E · ( Ê^{(k)} − Ê^{(k−1)} ) ] / scale
```

- 第一项 = **师兄提的增量 makespan**：本次分配把该 DAG 的预计完成时间推后了多少
- 第二项 = 该分配带来的预计能耗增量（由 λ_E 加权，与 J 中同一系数）
- `scale`：归一化尺度（建议用 `CLEAN_REWARD_TIME_REF = 60s`，使量级与其它项可比）
- **每一项都能追溯回 J** —— 这才叫"奖励为目标服务"

### 与当前奖励的差距
当前 reward = `−0.5·Σ时延 − 0.05·Σ任务能耗 − 0.08·移动能耗 + 8.0·完成DAG数 + 0.5·覆盖率`，
**不是任何 J 的增量分解**：`+8` 完成项比时延项重 4–16 倍 ⇒ 事实上在最大化**吞吐**，而论文头条报的是 **flowtime**。二者不是同一个目标。
