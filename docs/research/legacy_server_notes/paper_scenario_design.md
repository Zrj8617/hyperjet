## 🎯 研究场景: 智慧城市应急响应系统

### 场景背景

**应用场景**: 城市突发事件(如地震、火灾、大型活动)中的应急通信与计算服务

**核心问题**:
- 地面基础设施受损或过载
- 大量用户设备需要紧急服务(视频监控、人脸识别、路径规划、医疗诊断)
- 用户设备电量有限,需要无线充电
- 无人机需要协同提供边缘计算服务

**为什么需要超图建模?**
1. **复杂的协作关系**: 多个无人机可能同时服务同一用户
2. **任务依赖关系**: 一个应急任务可能需要多个子任务协同完成
3. **动态分组需求**: 无人机需要根据任务负载动态组队

## 🔬 研究问题定义

### 优化目标

**主目标**: 最小化系统总成本
```
minimize: Cost = α₁·Latency + α₂·Energy + α₃·(-Fairness) + α₄·OfflineRate
```

**子目标**:
1. **延迟最小化**: 任务完成时间(包括传输、计算、卸载)
2. **能耗最小化**: 无人机移动能耗 + 计算能耗 + 通信能耗
3. **公平性最大化**: 所有用户获得均等服务(Jain's Fairness Index)
4. **离线率最小化**: 避免用户设备电量耗尽

### 决策变量

**1. 轨迹规划** (连续动作)
```
trajectory_t = [Δx_t, Δy_t] ∈ [-1, 1]²
```

**2. 任务卸载决策** (离散动作)
```
offloading_t = {
    local: 0/1,      # 本地处理
    neighbor: 0/1,   # 卸载到邻居无人机
    mbs: 0/1         # 卸载到宏基站
}
```

**3. 缓存策略** (可选,初期可用启发式)
```
cache_t = file_id ∈ [0, NUM_FILES-1]
```

### 约束条件

1. **无人机约束**:
   - 最大速度: v_max = 15 m/s
   - 最小安全距离: d_min = 200m
   - 飞行高度: H = 100m (固定)
   - 覆盖半径: R = 100m

2. **通信约束**:
   - 带宽限制: B_edge = 40MHz, B_inter = 20MHz
   - 传输功率: P_comm = 0.5W
   - 信道模型: 自由空间路径损耗

3. **计算约束**:
   - 无人机计算能力: F_u ∈ [5, 20] GHz
   - 存储容量: S_u ∈ [40, 80] MB

4. **能量约束**:
   - 用户设备电池: B_max = 100J
   - 临界阈值: B_low = 30J
   - 无线充电功率: P_WPT = 500MW

## 🧩 超图建模方案

### 为什么需要超图?

**传统图的局限**:
- 图只能表示两两关系(边连接两个节点)
- 无法表示多个无人机协同服务同一用户
- 无法表示任务的多方依赖关系

**超图的优势**:
- 超边可以连接任意数量的节点
- 自然表示多方协作关系
- 适合建模复杂的任务依赖

### 超图构建方法

#### 层次1: 智能体协作超图

**节点**: 无人机 {UAV₁, UAV₂, ..., UAV_N}

**超边类型**:
1. **空间邻近超边** (Spatial Hyperedge)
   ```
   E_spatial = {UAV_i | dist(UAV_i, region_k) < R_sense}
   ```
   - 含义: 在同一感知范围内的无人机
   - 用途: 协同覆盖、避免碰撞

2. **服务协同超边** (Service Hyperedge)
   ```
   E_service = {UAV_i | UAV_i serves UE_j}
   ```
   - 含义: 服务同一用户的无人机组
   - 用途: 负载均衡、协同卸载

3. **缓存相似超边** (Cache Hyperedge)
   ```
   E_cache = {UAV_i | similarity(cache_i, cache_k) > θ}
   ```
   - 含义: 缓存内容相似的无人机
   - 用途: 内容共享、协同缓存

#### 层次2: 任务依赖超图 (可选,高级版本)

**节点**: 子任务 {Task₁, Task₂, ..., Task_M}

**超边**: 任务依赖关系
```
E_task = {Task_i | Task_i 是完成 Job_k 的必要子任务}
```

**示例**: 人脸识别任务
```
Job: 人脸识别
  ├─ Task1: 视频采集 (UE → UAV)
  ├─ Task2: 人脸检测 (UAV本地)
  ├─ Task3: 特征提取 (UAV本地或邻居)
  └─ Task4: 特征匹配 (MBS数据库)

超边: E_face_recognition = {Task1, Task2, Task3, Task4}
```

### 动态超图更新

**更新触发条件**:
1. 每隔 T_cluster = 50 步
2. 无人机位置变化超过阈值
3. 任务负载变化超过阈值

**更新方法**: 动态谱聚类
```python
# 伪代码
if step % T_cluster == 0:
    # 1. 收集状态历史
    state_history = collect_state_history(window=100)

    # 2. 谱聚类
    new_groups = SpectralClustering(state_history, n_clusters=[3,7])

    # 3. 稳定性检查
    if stability(new_groups, old_groups) > threshold:
        update_hypergraph(new_groups)
```

## 🤖 算法框架

### 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    环境 (Environment)                    │
│  - 无人机动态 (轨迹、能耗)                               │
│  - 用户设备 (移动、请求、电池)                           │
│  - 通信模型 (信道、速率)                                 │
└─────────────────────────────────────────────────────────┘
                          ↓ 观测
┌─────────────────────────────────────────────────────────┐
│              超图构建模块 (Hypergraph Builder)           │
│  - 空间邻近超边                                          │
│  - 服务协同超边                                          │
│  - 缓存相似超边                                          │
│  - 动态谱聚类                                            │
└─────────────────────────────────────────────────────────┘
                          ↓ 超图结构
┌─────────────────────────────────────────────────────────┐
│         超图卷积网络 (Hypergraph Convolution)            │
│  - 多层HGCN                                              │
│  - 组内信息聚合                                          │
│  - 组间信息传播                                          │
└─────────────────────────────────────────────────────────┘
                          ↓ 增强特征
┌─────────────────────────────────────────────────────────┐
│              多智能体强化学习 (MARL)                     │
│  - Actor网络 (输出混合动作)                              │
│    ├─ 轨迹头: [Δx, Δy]                                  │
│    └─ 卸载头: [local, neighbor, mbs]                    │
│  - Critic网络 (评估价值)                                 │
│  - 算法: MATD3 / MASAC                                   │
└─────────────────────────────────────────────────────────┘
                          ↓ 动作
┌─────────────────────────────────────────────────────────┐
│                执行与反馈 (Execution)                    │
│  - 轨迹更新                                              │
│  - 任务卸载                                              │
│  - 奖励计算                                              │
└─────────────────────────────────────────────────────────┘
```

### 核心创新点

1. **超图增强的观测表示**
   - 传统方法: 局部观测 + 注意力机制
   - 本文方法: 局部观测 + 超图卷积 + 动态分组

2. **混合动作空间的联合优化**
   - 传统方法: 只优化轨迹,卸载用启发式
   - 本文方法: 端到端学习轨迹和卸载决策

3. **动态分组机制**
   - 传统方法: 固定的智能体关系
   - 本文方法: 根据任务负载动态调整分组

## 📊 实验设计

### 对比基线 (Baselines)

1. **Random**: 随机动作
2. **Greedy**: 贪心策略(最近邻卸载)
3. **MADDPG**: 经典多智能体DDPG
4. **MATD3**: Multi-Agent TD3
5. **MATD3 + Attention**: 带注意力机制的MATD3
6. **HYGMA (Ours)**: MATD3 + 超图卷积 + 动态分组

### 消融实验 (Ablation Study)

| 变体 | 超图卷积 | 动态分组 | 混合动作 |
|------|---------|---------|---------|
| Baseline | ❌ | ❌ | ❌ |
| +HGCN | ✅ | ❌ | ❌ |
| +Grouping | ✅ | ✅ | ❌ |
| Full (Ours) | ✅ | ✅ | ✅ |

### 评估指标

**主要指标**:
1. **平均任务延迟** (ms)
2. **系统总能耗** (J)
3. **Jain公平性指数** (0-1)
4. **用户离线率** (%)

**次要指标**:
5. 收敛速度 (episodes)
6. 卸载成功率 (%)
7. 碰撞次数
8. 缓存命中率 (%)

### 实验参数

**环境参数**:
- 无人机数量: 5, 7, 10 (可扩展性测试)
- 用户设备数量: 100, 150, 200
- 区域大小: 700m × 700m
- 仿真时长: 1000 时间步/episode

**训练参数**:
- 总训练步数: 1M steps
- 学习率: Actor=9e-4, Critic=8e-4
- 批次大小: 128
- 折扣因子: γ=0.96

**超图参数**:
- 聚类间隔: 50 steps
- 最小分组数: 2
- 最大分组数: 5
- HGCN层数: 3
- 隐藏维度: 64

## 📌 关键技术难点

### 难点1: 超图构建的计算复杂度
**解决方案**:
- 使用KNN近似邻居搜索
- 限制超边的最大节点数
- 异步更新超图结构

### 难点2: 混合动作空间的训练稳定性
**解决方案**:
- 分阶段训练(先轨迹,后卸载)
- 使用课程学习(Curriculum Learning)
- 调整奖励权重

### 难点3: 动态分组的稳定性
**解决方案**:
- 设置稳定性阈值
- 限制分组变化频率
- 使用指数移动平均平滑状态
